# 迁移与回滚

## 上线前准备

1. 保留当前 Beszel 的镜像／二进制、Compose／1Panel 配置及环境变量。
2. 停止旧 Hub 后备份整个持久化目录，包含 `data.db`、`auxiliary.db`、`id_ed25519`、`storage`、备份等已有文件。不要在 SQLite 写入时直接复制孤立的 `data.db`；使用 PocketBase 备份或停机复制完整目录。
3. 创建独立的数据副本，让 monitor 对副本执行迁移。核对服务器 ID、历史数量、探测配置和 Agent 密钥。不要让两套 Hub 同时主动连接同一组生产 Agent。
4. 使用本地／临时端口核对公开字段、名称、favicon、主题和管理操作，然后再切换正式端口或反向代理。

## 数据变化

迁移 `1791580000_chenv` 增加 `chenv_config`、`chenv_systems`、`chenv_monitors`，存储站点及展示配置，避免修改 Agent 所用的主机连接记录。已有 Oracle ID `m9gh5qbz6fc3bw3` 默认公开；其他主机默认未公开。已有探测沿用原名称，没有独立名称时在脱敏模式不展示原目标。

迁移 `1791580100_chenv_tokens` 增加 `chenv_universal_tokens`，归属超级管理员。已有普通账户与历史数据保留。现有 Agent 的专用令牌和指纹继续工作，新建主机仍生成相同协议所用令牌；通用令牌自注册无需普通账户关系，新主机默认不公开。

chenv 模式允许无普通用户关系的主机，关闭批处理接口，关闭告警与通知执行，关闭旧网页入口。原始数据不破坏性删除。

## 更新

1. 停止 monitor，备份整个 `monitor_data` 和配置。
2. 记录当前镜像 ID，保留旧镜像，不执行清理旧镜像的命令。
3. 构建新版本，启动并验证 `/api/health`、公开页、管理员登录及 Agent 数据更新。
4. 如果失败，按下面的回滚流程处理。

## 回滚

停止新 Hub。恢复上线前完整数据目录和原部署配置，切换回保留的旧 Beszel 镜像／二进制，再启动旧 Hub。数据库及程序必须作为同一组备份回滚，避免继续使用修改后的权限／迁移状态。回滚将丢失升级后新增的数据，回滚前也可额外保存当前数据副本。

迁移的 down 函数只删除新增展示／超级管理员令牌集合；首选完整备份恢复，不在生产库中试验删除集合。项目没有自动把生产环境切换到本地预览。

## 1Panel

可通过 1Panel 的自定义编排使用根目录 `compose.yml`。构建上下文需包含完整源码，镜像构建完成后绑定备份复制得到的数据目录。安装命令使用浏览器实际访问的 Hub 地址；应从被监控服务器可访问该地址。
